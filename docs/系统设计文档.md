# 学生选课管理系统 — 系统设计文档

> 文档版本：v1.0  
> 适用对象：开发人员、答辩评审、部署运维、二次开发人员  
> 技术栈：Spring Boot 2.7 + Vue 2.7 + Element UI + MyBatis-Plus + MySQL  

---

## 第一章 项目概述

### 1.1 项目背景

高等学校教学管理信息化建设持续推进，选课、排课、成绩管理已成为教务日常工作中最高频的业务之一。传统线下登记、Excel 手工汇总方式存在信息分散、更新滞后、易出错、难以统计等问题。随着在校生规模扩大与课程类型多样化，教务管理人员亟需一套结构清晰、操作便捷、可快速落地的信息化管理系统。

本系统面向中小型院校或教学实训场景，聚焦“学生选课管理”核心链路，覆盖学生与教师基础信息维护、课程与排课管理、选课与限制规则配置、公告发布以及成绩录入等完整闭环。系统采用前后端分离架构，便于独立部署、独立扩展，也适合作为计算机相关专业毕业设计、课程设计的完整案例工程。

### 1.2 建设目标

1. **业务完整**：覆盖学生、教师、课程、公告、排课、选课、选课限制、成绩八大核心模块，每个模块均支持新增、修改、删除与条件查询。  
2. **架构清晰**：前端负责交互展示，后端负责业务规则与数据持久化，数据库负责结构化存储。  
3. **易于部署**：提供完整 SQL 脚本、配置说明与部署文档，保证在常见 Windows/Linux 开发环境可快速运行。  
4. **可扩展**：预留接口规范与模块边界，便于后续扩展学生端登录、教师端成绩录入、冲突检测、学分统计等高级能力。  
5. **可演示**：内置演示数据，登录后即可查看统计面板并操作各业务页面。

### 1.3 适用场景

- 高校教务处日常管理演示系统  
- 计算机专业毕业设计 / 课程设计  
- SpringBoot + Vue 前后端分离教学实训  
- 二次开发的基础脚手架（CRUD 管理系统）

### 1.4 非目标范围（本期不做）

为控制交付边界，本期不实现以下能力（可在扩展章节中继续开发）：

- 学生端自助选课门户（当前为管理端代录）  
- 复杂课表冲突自动检测（教师冲突、教室冲突、学生时间冲突）  
- 工作流审批（选课申请审核）  
- 短信 / 邮件通知  
- 细粒度 RBAC 多角色权限（当前为管理员统一管理）  
- 支付、评教、毕业论文管理等外围教务子系统

## 第二章 需求分析

### 2.1 角色分析

本期系统以**系统管理员**为主角色：

| 角色 | 职责 | 主要操作 |
|------|------|----------|
| 系统管理员 | 维护基础数据与选课业务 | 登录、各模块增删改查、查看统计 |

后续可扩展：

| 角色 | 可扩展能力 |
|------|------------|
| 学生 | 查看可选课程、提交选课、退课、查成绩 |
| 教师 | 查看授课班、录入成绩、发布课程通知 |
| 教务员 | 审核选课、维护限制规则、发布公告 |

### 2.2 功能需求清单

#### 2.2.1 学生管理

- 新增学生信息（学号、姓名、性别、年级、专业、班级、联系方式等）  
- 修改学生信息  
- 删除学生信息  
- 按学号 / 姓名 / 专业 / 班级关键词检索  
- 分页展示学生列表  

#### 2.2.2 教师管理

- 新增教师（工号、姓名、性别、职称、院系、联系方式）  
- 修改 / 删除教师  
- 关键词检索与分页  

#### 2.2.3 课程信息管理

- 维护课程编号、名称、学分、学时、类型（必修/选修）、开课院系、简介  
- 支持启停状态  

#### 2.2.4 公告信息管理

- 发布选课通知、考试安排等公告  
- 支持发布 / 下架状态切换  

#### 2.2.5 排课信息管理

- 将课程与教师、学期、上课时间、教室、容量关联  
- 展示已选人数 / 容量  
- 支持开课 / 停开  

#### 2.2.6 选课信息管理

- 为学生指定排课记录完成选课  
- 修改选课状态（已选 / 已退）  
- 删除选课记录并回滚容量计数  

#### 2.2.7 选课限制管理

- 配置全局或按课程的限制条件：专业、年级、学分上下限、选课时间窗  
- 生效 / 失效状态控制  

#### 2.2.8 学生成绩管理

- 录入平时成绩、考试成绩  
- 可自动计算总评（默认 4:6）  
- 按学生 / 课程查询  

### 2.3 非功能需求

1. **可用性**：界面简洁，菜单清晰，操作路径短。  
2. **性能**：常规分页查询在万级数据量下可接受（本系统以教学演示为主）。  
3. **安全性**：接口需登录鉴权；生产环境应对密码加密、HTTPS、SQL 注入防护加强。  
4. **可维护性**：模块边界清楚，命名统一，文档齐全。  
5. **兼容性**：后端 Java 8+，前端现代浏览器。

### 2.4 业务规则摘要

1. 学号、工号、课程编号唯一。  
2. 同一学生不可重复选择同一排课。  
3. 选课不得超过排课容量。  
4. 停开课程不允许新增选课。  
5. 成绩总评可自动计算：`总评 = 平时*0.4 + 考试*0.6`。  
6. 删除有效选课记录时，排课已选人数减一。

## 第三章 系统总体设计

### 3.1 架构风格

系统采用经典的 **B/S + 前后端分离** 架构：

```text
浏览器 (Vue + Element UI)
        |  HTTP / JSON
Spring Boot REST API
        |  JDBC / MyBatis-Plus
      MySQL
```

分层说明：

1. **表现层（前端）**：负责路由、表单校验、表格展示、弹窗编辑、Token 存储。  
2. **控制层（Controller）**：接收请求、参数校验、调用 Mapper、封装统一响应。  
3. **持久层（Mapper）**：基于 MyBatis-Plus 完成 CRUD 与联表分页。  
4. **数据层（MySQL）**：保存业务实体与关联关系。

### 3.2 技术选型理由

| 技术 | 选型理由 |
|------|----------|
| Spring Boot | 约定优于配置，快速集成 Web、数据源、校验 |
| MyBatis-Plus | 减少样板代码，内置分页插件，适合 CRUD 项目 |
| Vue 2 + Element UI | 国内管理系统成熟方案，组件丰富，学习成本低 |
| Axios | 统一拦截请求/响应，便于挂载 Token |
| MySQL | 关系型数据库，适合强关联教务数据 |

### 3.3 模块划分

后端按业务域拆分为多个 Controller：

- AuthController：登录认证  
- DashboardController：首页统计  
- StudentController / TeacherController / CourseController  
- AnnouncementController / ScheduleController  
- SelectionController / LimitController / GradeController  

前端按页面拆分：

- Login / Dashboard  
- Student / Teacher / Course / Announcement  
- Schedule / Selection / Limit / Grade  

### 3.4 统一响应与错误处理

后端统一返回：

```json
{ "code": 200, "message": "success", "data": {} }
```

业务失败返回 `code=500` 或 `400`，未登录返回 `401`。全局异常处理器捕获未处理异常，避免堆栈直接暴露给前端。

### 3.5 认证设计

演示环境采用内存 Token：

1. 登录成功生成 UUID Token。  
2. Token 与管理员 ID 存入 `ConcurrentHashMap`。  
3. 拦截器校验 `Authorization: Bearer <token>`。  
4. 退出时删除 Token。

说明：该方案便于本地演示。生产建议升级为 JWT + Redis，并增加过期时间、刷新机制与黑名单。

## 第四章 数据库设计

### 4.1 设计原则

1. 每张业务表包含主键 `id`。  
2. 重要业务编号字段建立唯一索引（学号、工号、课程编号）。  
3. 关联表保存外键语义字段（如 `student_id`、`course_id`），便于联查。  
4. 统一使用 `create_time`、`update_time` 记录审计信息。  
5. 字符集采用 `utf8mb4`，兼容中文与特殊符号。

### 4.2 概念模型（文字 ER）

- 一个教师可讲授多个排课班  
- 一门课程可对应多个排课班  
- 一个学生可选择多个排课班（选课记录）  
- 一条选课记录对应一个学生 + 一个排课  
- 成绩记录关联学生与课程（可选关联排课）  
- 选课限制可针对某课程，也可作为全局规则  
- 公告相对独立，由管理员维护  

### 4.3 逻辑表清单

| 表名 | 中文名 | 说明 |
|------|--------|------|
| sys_admin | 管理员 | 登录账号 |
| student | 学生 | 学生基础档案 |
| teacher | 教师 | 教师基础档案 |
| course | 课程 | 课程目录 |
| announcement | 公告 | 通知公告 |
| course_schedule | 排课 | 学期开课班次 |
| course_selection | 选课 | 学生选课结果 |
| selection_limit | 选课限制 | 规则配置 |
| grade | 成绩 | 成绩明细 |

### 4.4 关键字段说明（节选）

#### student

- `student_no`：学号，唯一  
- `name`：姓名  
- `grade`：年级（如 2024）  
- `major`：专业  
- `class_name`：班级  
- `status`：1 正常 / 0 禁用  

#### course_schedule

- `course_id` / `teacher_id`：关联课程与教师  
- `semester`：学期编码  
- `weekday`：星期 1-7  
- `section_start` / `section_end`：节次区间  
- `capacity` / `selected_count`：容量与已选人数  

#### course_selection

- `student_id` + `schedule_id`：唯一约束，防止重复选课  
- `status`：1 已选 / 0 已退  

#### grade

- `usual_score` / `exam_score` / `total_score`  
- 后端在总评为空时按权重自动计算  

### 4.5 初始化数据策略

SQL 脚本内置：

- 1 个管理员  
- 3 名学生、3 名教师、3 门课程  
- 2 条公告、3 条排课、2 条选课、2 条限制、2 条成绩  

便于部署后立即演示全流程。

## 第五章 后端详细设计

### 5.1 工程结构

```text
backend/
  pom.xml
  src/main/java/com/course/
    CourseApplication.java
    common/          # Result、异常处理、分页参数
    config/          # CORS、MyBatis-Plus、WebMvc
    controller/      # REST 接口
    entity/          # 实体
    interceptor/     # 鉴权拦截器
    mapper/          # MyBatis Mapper
  src/main/resources/
    application.yml
```

### 5.2 配置要点

- 服务端口：`8088`  
- 上下文：`/api`  
- 数据源：MySQL `course_selection`  
- Jackson 时区：`Asia/Shanghai`  
- MyBatis-Plus：驼峰映射 + 分页插件  

### 5.3 接口分层约定

Controller 负责：

1. 接收查询参数与请求体  
2. 组装 QueryWrapper 或调用自定义联表 SQL  
3. 执行业务校验（唯一性、容量等）  
4. 返回 `Result`

复杂联表查询使用注解 SQL：

- 排课分页联查课程名、教师名  
- 选课分页联查学生、课程、教师、学期  
- 成绩分页联查学生、课程  
- 限制分页联查课程名  

### 5.4 选课事务设计

选课新增使用 `@Transactional`：

1. 校验是否重复  
2. 校验排课状态与容量  
3. 插入选课记录  
4. 更新排课已选人数  

删除同样在事务中回滚容量，保证计数一致性。

### 5.5 成绩计算设计

当 `totalScore` 为空，且平时、考试成绩均非空：

```text
total = usual * 0.4 + exam * 0.6
```

保留两位小数，四舍五入。管理员也可手动覆盖总评。

### 5.6 安全性说明与改进建议

当前实现适合课程设计演示。若上线生产，建议：

1. 密码 BCrypt 加密存储  
2. JWT 鉴权 + 过期控制  
3. 接口限流与操作日志  
4. 关键操作二次确认与软删除  
5. 参数校验注解增强（`@NotBlank` 等）  
6. 防止水平越权（多角色场景）

## 第六章 前端详细设计

### 6.1 工程结构

```text
frontend/
  public/index.html
  src/
    main.js
    App.vue

    utils/request.js
```

### 6.2 路由与布局

- Hash 模式路由，部署更简单  
- 登录页独立；业务页嵌套在 `MainLayout`  
- 路由守卫：无 Token 跳转登录  

左侧菜单对应八大业务模块 + 首页概览。

### 6.3 请求封装

- `baseURL = /api`  
- 请求拦截器自动附加 Token  
- 响应拦截器统一处理 `code != 200` 与 `401`  

开发环境通过 `vue.config.js` 代理到后端 `8088`，避免跨域。

### 6.4 页面交互模式

各管理页采用统一交互范式：

1. 顶部工具栏：关键词搜索 + 新增按钮

3. 底部分页  
4. 弹窗表单：新增 / 修改共用

### 6.5 可用性设计

- 表格固定操作列，宽屏/窄屏均可操作

- 首页统计卡片帮助快速了解系统数据规模  

### 6.6 前端扩展建议

- 引入 Vuex / Pinia 管理用户状态  
- 增加导出 Excel  
- 增加课表日历视图  
- 增加表单草稿与批量导入

## 第七章 核心业务流程

### 7.1 基础数据准备流程

```text
维护学生 -> 维护教师 -> 维护课程 -> 发布公告
```

这是排课与选课的前置条件。

### 7.2 排课流程

```text
选择课程 + 教师 + 学期 + 星期节次 + 教室 + 容量
        -> 生成排课班次
```

排课记录是选课的直接对象。一门课程可开设多个班次。

### 7.3 选课流程（管理端代录）

```text
选择学生 + 选择排课班次
  -> 校验重复
  -> 校验容量与开课状态
  -> 写入选课
  -> 已选人数 +1
```

### 7.4 选课限制配置流程

管理员可配置：

- 全局学分上下限与选课时间窗  
- 某课程仅允许特定专业 / 年级  

当前版本以规则维护为主，学生端自动校验可在二期接入选课提交环节。

### 7.5 成绩录入流程

```text
选择学生 + 课程 + 学期
  -> 录入平时分/考试分
  -> 自动或手动生成总评
  -> 保存
```

### 7.6 典型演示脚本（答辩可用）

1. 登录系统，展示首页统计。  
2. 新增一名学生与一门课程。  
3. 为该课程新增排课。  
4. 给学生完成选课，观察容量变化。  
5. 录入成绩并展示自动总评。  
6. 发布一条选课公告。  
7. 修改一条选课限制规则。  

整套演示约 5~8 分钟，覆盖系统主要价值点。

## 第九章 测试说明

### 9.1 测试策略

以功能测试为主，辅以关键路径手工验证：

1. 登录成功 / 失败  
2. 各模块新增成功

7. 重复选课失败

### 9.2 测试用例示例

| 编号 | 用例 | 预期 |
|------|------|------|
| T01 | 正确账号登录 | 进入首页并保存 Token |

### 9.3 回归建议

每次改动选课/排课相关逻辑后，必须回归容量计数与重复选课校验，避免出现“超选”或“计数漂移”。

## 第十章 部署与运维

### 10.1 环境准备

安装 JDK、Maven、Node.js、MySQL，并确认端口：

- MySQL：3306  
- 后端：8088  
- 前端开发：8080  

### 10.2 部署步骤摘要

1. 执行 SQL 初始化  
2. 修改 `application.yml` 数据库账号  
3. 启动后端  
4. 安装前端依赖并启动 / 构建  
5. 浏览器登录验收  

详细步骤见《部署说明.md》。

### 10.3 日志与排查

- 后端控制台可看到 SQL 日志（开发环境开启）

## 第十三章 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 演示环境明文密码 | 安全风险 | 上线前改为加密存储 |
