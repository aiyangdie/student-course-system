## 四、功能模块（必须全部实现）

每个模块都要支持：**分页查询、关键词检索、新增、修改、删除**。

### 1. 学生管理

字段建议：学号、姓名、性别、年级、专业、班级、手机、邮箱、状态  
约束：学号唯一

### 2. 教师管理

字段建议：工号、姓名、性别、职称、院系、手机、邮箱、状态  
约束：工号唯一

### 3. 课程信息管理

字段建议：课程编号、课程名称、学分、学时、类型（必修/选修）、开课院系、简介、状态  
约束：课程编号唯一

### 4. 公告信息管理

字段建议：标题、内容、发布人、状态（发布/下架）、时间

### 5. 排课信息管理

字段建议：课程、教师、学期、星期、开始节次、结束节次、教室、容量、已选人数、状态（开课/停开）  
列表需联查显示课程名、教师名

### 6. 选课信息管理

字段建议：学生、排课班次、选课时间、状态（已选/已退）、备注  
列表需联查显示学号、学生名、课程名、教师名、学期

**业务规则（后端必须校验，不能只靠前端）：**

1. 同一学生不能重复选择同一排课（已选状态）
2. 排课必须存在且为开课状态
3. 已选人数不能超过容量
4. 新增「已选」时 `selected_count + 1`；删除已选或改为已退时 `- 1`
5. 退课后再次选课：应更新原记录，避免唯一索引冲突导致 500
6. 直接新增「已退」记录不得占用容量
7. 选课时校验生效中的选课限制（时间窗、专业、年级；课程级或全局）

### 7. 选课限制管理

字段建议：限制课程（可空=全局）、限选专业、限选年级、最小/最大学分、开始/结束时间、备注、状态  
说明：学分上下限字段可先存储；至少实现时间窗 + 专业 + 年级在选课提交时的强校验

### 8. 学生成绩管理

字段建议：学生、课程、学期、平时成绩、考试成绩、总评、备注  
规则：若平时与考试都有值，总评按 `平时*0.4 + 考试*0.6` **始终重算**（避免前端带回旧总评导致不更新）

### 9. 首页概览（Dashboard）

必须真实、可点击：

- 统计卡片：学生、教师、课程、排课、有效选课、公告、成绩、生效限制等（数字来自数据库实时统计）
- 点击卡片跳转对应模块
- 最新公告 / 最近选课 / 近期排课列表（可跳转）
- 快捷入口（新增学生、排课、选课、录成绩、发公告等）
- **不要**在首页展示大段系统说明书和默认密码明文

### 10. 登录鉴权

- 登录成功返回 Token
- 除 `/auth/login` 外，接口需 `Authorization: Bearer <token>`
- Token 需有过期时间（如 12 小时）
- 前端 401：清理本地登录态并跳转登录页，避免未捕获异常红屏
- 密码：BCrypt 校验；兼容极旧明文仅作迁移可选，开源脚本默认 BCrypt

## 五、架构要求

### 总体

```text
浏览器 (Vue + Element UI)
   │  HTTP JSON + Bearer Token
Spring Boot REST (/api)
   │  MyBatis-Plus
MySQL (course_selection)
```

### 后端分层建议

```text
com.xxx
  ├── common        # Result、全局异常
  ├── config        # CORS、分页、拦截器注册
  ├── interceptor   # Token 鉴权
  ├── controller    # REST
  ├── entity        # 表实体（联查字段 exist=false）
  └── mapper        # BaseMapper + 必要联表 SQL
```

### 统一响应

```json
{ "code": 200, "message": "success", "data": {} }
```

`401` 未登录；业务失败返回明确中文 message。

### 前端结构建议

```text
src/
  api/ request 封装
  router/ 路由守卫
  layout/ 侧栏布局
  views/ Login、Dashboard、各业务页
```

页面交互统一范式：

- 顶栏：搜索 + 新增
- 中部：表格 + 状态 Tag
- 底部分页
- 弹窗表单：新增/修改共用
- 删除二次确认

## 六、数据库设计要求

至少包含表：

- `sys_admin`
- `student`
- `teacher`
- `course`
- `announcement`
- `course_schedule`
- `course_selection`（`student_id + schedule_id` 唯一）
- `selection_limit`
- `grade`

要求：

1. 主键自增；重要编号唯一索引
2. `create_time` / `update_time`
3. 脚本可重复执行（`DROP` + `CREATE` 或等价方式）
4. 内置足够演示数据（学生/教师/课程/排课/选课/公告/限制/成绩）
5. 选课限制时间窗覆盖「当前可演示日期」，避免一上线就因过期拦截全部选课
6. **导入方式必须保证中文不损坏**（文档中明确禁止易损坏中文的导入姿势）

## 七、配置与安全（开源友好）

1. 仓库中的 `application.yml` **不得**提交真实本机数据库密码  
2. 提供 `application-example.yml`；本地用 `application-local.yml`（gitignore）或文档说明改密  
3. 关闭默认 SQL 控制台全量打印（或仅本地开启）  
4. 写 `SECURITY.md`：已做措施 + 已知限制（内存 Token、宽松 CORS、无细粒度 RBAC、无限流等）  
5. 不要把 GitHub Token、云密钥、ApiKey 提交进仓库
